# Process observations and bounded experiments

Use explicit session IDs/log paths plus repository/worktree identity, task/time ranges and retained attribution evidence. Branch name alone is weak attribution. Keep raw logs private and sanitize before model input. Unknown/ambiguous data stays partial, not zero. Process completeness is independent of product review.

`import-process` consumes schema_version 1, run_id, attribution, receipts and observations. Attribution has repository_identity from the run, sessions, status (exact/partial/unknown) and evidence references. Receipts use the existing Oracle response format: provider, session_id, schema_version, updated_at, coverage and responses. Claude responses have message_id, request_id and counters input_tokens, cache_creation_input_tokens, cached_input_tokens, output_tokens, reasoning_output_tokens. Repeated streaming/cumulative response counters count maxima once; reasoning is already part of output. Session-wide cumulative counters without response identity are unsupported/partial. This adapter does not read all host logs or depend on Oracle at runtime. Supply previously generated, redacted receipts; unknown providers remain partial. Pricing is unavailable in 1.0, not an invented saving or invoice.

The Codex package intentionally retains this validated receipt contract. Native Codex session JSONL, exported cumulative usage and other provider formats are not newly validated by the host port. Leave those counters unknown/partial. An attributed observation of actual tool failures or context reads can still motivate an experiment without inventing token totals, pricing or savings. Missing process telemetry remains separate from product readiness.

Each process observation has id, claim, events, evidence and limitations. Repeated actual failures can justify setup investigation. No-call evidence does not establish that a server cost tokens. An expensive model on a simple task justifies an experiment, not a claim that another model would succeed. Repeated reads require necessity/cache investigation. Renaming a folder is not assumed to change context loading. Report measured waiting, active work, tool time and interruptions separately when available; do not recursively audit the audit.

`hypothesis` takes schema_version, id, origin_evidence, claim, population, intervention, baseline, metrics, success_criteria, failure_criteria, readiness (`ready`/`not_ready`), missing (array) and package_root (beside the input JSON). Include actual provider/model/version/settings in baseline/intervention; test one primary intervention. The package root contains README.md, prompt.md, sample/, environment/, evaluation/ and reference/. Pin tools, dependency locks, source/data, rubric/evaluator and reviewed reference provenance. A private pinned manifest with extraction instructions can replace unavailable source; label unavailable environments `not_ready` and list missing items. An empty hypothesis index is a valid outcome.

The full `hypothesis-<id>.zip` is evaluator-private and includes hypothesis.yml (JSON-compatible YAML). `candidate-<id>.zip` contains only prompt.md, sample and environment. Supply only the candidate archive to an isolated candidate environment. Keep evaluator/reference outside its filesystem and credentials; the future harness must enforce this. Packaging rejects symlinks, direct hidden-folder links in the prompt and exact copied hidden files. It cannot determine whether an answer is semantically leaked in arbitrary prose: independently inspect candidate material before trials. Do not mark an experiment self-contained when inaccessible source, tools or devices are still needed.

Experiments prioritize correctness/regressions before cost. Include semantic near-misses and rejected consolidation cases. Use representative tasks, repetitions and held-out tasks; a small pilot is not universal evidence. Measure total cost including retries/failures, cost per successful task, token categories, latency, failure rates and uncertainty. Randomize/interleave order where practical, keep tools/permissions/start state constant, and separate environment interventions. Predefine quality thresholds and failure criteria. The plugin emits packages; it neither runs experiments nor promotes model routing/configuration changes. Survey existing evaluation tools before building the later harness.
